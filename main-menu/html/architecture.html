Inference Flow — ทุก API call

  1. Claude Desktop ส่ง POST /v1/chat/completions พร้อม Authorization: Bearer {JWT} ไป Gateway (:4100)
  2. Gateway ตรวจ JWT — iss, aud, exp, signature (RS256) ดึง JWKS จาก Authentik (cache 1 ชม.)
  3. Guardrail ตรวจ groups: claude-users/claude-admins allow, claude-suspended deny — strip spoofing headers
  4. Gateway สลับเป็น LITELLM_MASTER_KEY แล้วส่งต่อไป LLM Server พร้อม x-authenticated-user
  5. LLM Server route ตาม model ใน request → เลือก physical model ที่ map ไว้ → ส่งไป OpenCode Zen
  6. upstream ตอบกลับเป็น streaming → LiteLLM → Gateway → Claude Desktop
  7. OTel collector เก็บ telemetry ส่ง Loki → ดูใน Grafana

Guardrail — การป้องกันด้านความปลอดภัย

Guardrail ฝังอยู่ใน Claude Gateway ทำงานก่อนส่งต่อ request ไป LiteLLM เสมอ:

🔐 JWT Verification (RS256)

ยืนยัน signature ด้วย JWKS จาก Authentik, ตรวจ iss/aud/exp (30s leeway), cache 1 ชม. — ถ้า Authentik ล่มใช้ cache เดิม, ไม่มี → 503 (fail closed)

👥 RBAC Groups

claude-users และ claude-admins = allow · claude-suspended = deny. ปฏิเสธถ้าไม่อยู่ใน group ที่อนุญาต

🛡️ Anti-spoofing

Strip x-authenticated-user / x-authenticated-sub ที่ client ส่งมาเสมอ — ป้องกันการปลอมตัวตน

🔒 Algorithm Lockdown

ปฏิเสธ alg: none และ HS256 — กัน algorithm confusion attack ที่อาจทำให้ verify ผ่านด้วย public key

🔑 Master Key Isolation

LiteLLM (:4000) expose เฉพาะ internal network — bypass Gateway ไม่ได้. Master-key caller ส่งต่อตามต้นฉบับ

🌐 MCP Isolation

MCP servers bind เฉพาะ 127.0.0.1 ไม่เปิดออก internet. Secrets และ tokens ถูก gitignore ทั้งหมด
