ภาพรวมระบบ

claude-3P คือชุดระบบที่ทำให้ผู้ใช้ล็อกอินด้วย OIDC SSO (Authentik) แล้วเรียก Claude / open-source LLM ผ่าน LiteLLM proxy ได้จาก Claude Desktop / Claude Code โดยตรง พร้อม MCP tools สำหรับงานเอกสาร (Gmail, Calendar, Sheets/Docs/Drive, Maps) และ web search ผ่าน SearXNG — โดยไม่ต้องส่งข้อมูลออก Anthropic API โดยตรง

ทั้งหมดรันได้ด้วยคำสั่งเดียวที่ root: docker compose up -d

Authentik

หน้าที่: OIDC Identity Provider — จัดการผู้ใช้, กลุ่ม (RBAC), และ OAuth/OIDC clients

เวอร์ชัน: 2025.10.0 · PostgreSQL 16 · Redis 7

พอร์ต: 9000 (internal — เข้าผ่าน reverse proxy หรือ Cloudflare Tunnel)

การเชื่อมต่อ:

  • Claude Desktop ล็อกอินผ่าน https://${AUTH_DOMAIN}/application/o/authorize/
  • Claude Gateway ดึง JWKS จาก http://authentik-server:9000/application/o/claude-desktop/jwks/
  • Blueprints ที่ gateway-auth/authentik/blueprints/claude-desktop.yaml กำหนด groups: claude-users, claude-admins, claude-suspended

ข้อจำกัด: Access token TTL 8 ชม. (demo) — ปรับได้ที่ blueprint

Claude Gateway

หน้าที่: FastAPI proxy ที่ยืนยัน JWT (RS256) จาก Authentik แล้วส่งต่อไป LiteLLM ด้วย master key

พอร์ต: 4100

การเชื่อมต่อ:

  • รับ POST /v1/chat/completions จาก Claude Desktop
  • ตรวจ JWT: iss, aud, exp, groups (RBAC)
  • Strip x-authenticated-user ที่ client ส่งมา (กัน spoofing)
  • ส่งต่อไป LiteLLM พร้อม x-authenticated-user: <username>
  • Master-key caller → ส่งต่อตามต้นฉบับ

Health: GET /health

LiteLLM

หน้าที่: OpenAI-compatible proxy สำหรับ routing ไป upstream LLMs

พอร์ต: 127.0.0.1:4000 (internal — ไม่ expose ออกเพื่อกัน bypass)

การเชื่อมต่อ:

  • รับจาก Claude Gateway ด้วย LITELLM_MASTER_KEY
  • Route ตาม config.yaml: Ollama Cloud, OpenCode
  • DB เก็บ model config / spend tracking

UI: http://localhost:4000/ui (login: LITELLM_UI_USERNAME / LITELLM_UI_PASSWORD)

Gmail MCP

หน้าที่: MCP server สำหรับอ่าน/เขียน/ค้นอีเมลผ่าน Gmail API

พอร์ต: 127.0.0.1:3001

การเชื่อมต่อ:

  • Claude Desktop เรียกผ่าน Streamable HTTP: http://127.0.0.1:3001/mcp
  • OAuth ครั้งแรก: docker compose --profile auth up -d gmail-auth → เปิด http://localhost:3101
  • Token เก็บที่ secrets/gmail-token.json

ข้อจำกัด: ต้องมี Google Cloud project + OAuth client (Desktop app)

Workspace MCP

หน้าที่: MCP server สำหรับ Google Sheets, Docs, Drive

พอร์ต: 127.0.0.1:3003

การเชื่อมต่อ:

  • Claude Desktop เรียก: http://127.0.0.1:3003/mcp
  • OAuth ครั้งแรก: docker compose --profile auth-workspace up -d workspace-auth → http://localhost:3103
  • ใช้ credentials ร่วมกับ Gmail MCP

Maps MCP

หน้าที่: MCP server สำหรับ Google Maps — ค้นหาสถานที่, เส้นทาง, geocoding

พอร์ต: 127.0.0.1:3004

การเชื่อมต่อ:

  • Claude Desktop เรียก: http://127.0.0.1:3004/mcp
  • ต้องมี MAPS_API_KEY ใน .env

SearXNG

หน้าที่: Self-hosted meta-search engine — รวมผลจากหลาย search engine โดยไม่ track

พอร์ต: 8888

การเชื่อมต่อ:

  • ผู้ใช้เข้า UI ที่ http://localhost:8888
  • Search Adapter เรียกผ่าน http://searxng:8080 (internal)
  • ตั้งค่าที่ cowork-search/searxng/settings.yml

Search Adapter

หน้าที่: FastAPI HTTPS wrapper รอบ SearXNG สำหรับ Claude tools เรียกใช้

พอร์ต: 8090 (self-signed TLS)

การเชื่อมต่อ:

  • รับ query แปลงเป็น SearXNG API call
  • เสิร์ฟ self-signed cert จาก cowork-search/certs/

Grafana

หน้าที่: Dashboard สำหรับ visualization logs และ metrics

พอร์ต: 127.0.0.1:23000

การเชื่อมต่อ:

  • Login: admin / ${GRAFANA_ADMIN_PASSWORD}
  • Dashboard เริ่มต้น: cowork-overview
  • Provisioning อัตโนมัติจาก cowork-otel-grafana/grafana/provisioning/

Loki

หน้าที่: Log aggregation — เก็บ logs จากทุก service

พอร์ต: internal เท่านั้น (เข้าผ่าน Grafana)

การเชื่อมต่อ:

  • รับ logs จาก OTel Collector
  • สอบถามด้วย LogQL ใน Grafana
  • Volume: loki-data

OpenTelemetry Collector

หน้าที่: รับ OTLP HTTP (logs/metrics/traces) แล้วส่งต่อไป Loki

พอร์ต: 24318 (OTLP HTTP)

การเชื่อมต่อ:

  • Service ส่ง telemetry มาที่ http://<host>:24318/v1/logs
  • Config ที่ cowork-otel-grafana/otel/otel-collector-config.yaml

Security Model

  • JWT verification: RS256 only, JWKS cached, iss/aud/exp required, 30s leeway
  • Anti-spoofing: client-supplied x-authenticated-user/x-authenticated-sub ถูก strip เสมอ
  • Algorithm lockdown: ปฏิเสธ alg: none และ HS256
  • JWKS stale-while-error: ถ้า Authentik ล่ม ใช้ cache เดิม; ไม่มี → 503 (fail closed)
  • LiteLLM isolation: port 4000 expose เฉพาะ internal — bypass gateway ไม่ได้
  • MCP isolation: bind เฉพาะ 127.0.0.1
  • Secret hygiene: .env, secrets/, *.pem, token*.json ถูก ignore
  • RBAC groups: claude-users (allow), claude-admins (allow), claude-suspended (deny)
